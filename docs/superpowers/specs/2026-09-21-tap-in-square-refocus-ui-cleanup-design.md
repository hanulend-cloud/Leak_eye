# 사각블록 내부 터치 재초점 + AF 영역 확대 + 프리뷰 폭 맞춤 + UI 통일 설계

## 배경 / 목표

1. 지금은 화면 어디를 터치하든 그 위치로 평가영역 사각형이 이동하면서 재초점을 시도한다. 사용자가 실기기에서 써보니 AF가 계속 잘 안 잡히고, 사각형이 탭할 때마다 옮겨다니는 것도 불편하다는 피드백 — **사각형은 화면 중심에 고정하고, 그 사각형 "안쪽"을 터치했을 때만 그 자리에서 재초점을 시도**하도록 바꾼다. 사각형 바깥을 터치하면 아무 반응도 하지 않는다.
2. AF가 잘 안 잡히는 문제를 개선하기 위해 AF 영역(초점을 잡을 범위) 크기를 크롭 영역 폭의 5% → 20%로 넓힌다. 대비가 적은 장면(빛샘 테스트용 어두운 박스 등)에서도 초점 잡을 대상이 넓어져 AF 성공률이 올라간다.
3. 프리뷰 화면이 작게 보이는 문제 — 현재 `layoutPreview()`는 화면비에 따라 "폭 우선" 또는 "높이 우선" 중 하나를 선택하는데, 기기 화면비에 따라 높이를 우선해 폭이 좁게 표시되는 경우가 있었다. 항상 화면 폭을 꽉 채우도록 바꾼다(높이가 넘치면 위아래가 살짝 잘려 보이는 것은 허용).
4. 상하 텍스트/버튼 줄의 여백을 줄여 프리뷰에 세로 공간을 더 확보한다.
5. 전체 UI 스타일을 통일한다 — 색상 값을 몇 개의 이름 붙인 상수로 정리하고, 지금 제각각인 버튼 스타일(캡처/스윕 버튼은 시스템 기본 스타일, 줌/비율 버튼만 별도 색)을 전부 같은 스타일(진회색 배경 + 흰 글씨, 선택된 비율 버튼만 강조색)로 통일한다.

## 범위 밖

- AF 알고리즘 자체(연속촬영 모드 변경, 수동 초점 스캔 등) 변경
- 사각형을 다시 드래그로 옮기는 기능(요구사항이 "고정 위치, 안쪽 터치로 재초점"이므로 이동 기능은 제거)
- 디자인 시스템 라이브러리 도입(Material Components 등) — 순수 Android View의 색상/텍스트 크기/패딩 값 정리 수준

## 컴포넌트 설계

### 1. `EvaluationOverlayView.containsPoint(x, y)`

`onDraw()`가 사각형을 그릴 때 쓰는 것과 정확히 같은 계산(`SquareGeometry.squareSide`, `SquareGeometry.clampCenter`)을 재사용해 주어진 뷰 좌표가 현재 그려진 사각형 내부인지 판정하는 새 public 메서드. 그리기 로직과 판정 로직이 어긋나지 않도록 같은 클래스 안에 둔다.

### 2. `MainActivity` 터치 리스너 변경

`preview.setOnTouchListener(...)`를 "터치 지점이 `overlay.containsPoint(x, y)`이면 `focusAt(overlay.getCenterX(), overlay.getCenterY())` 호출, 아니면 아무 것도 안 함"으로 교체. 사각형은 더 이상 탭 위치로 옮겨지지 않으므로(줌 토글 시 자동 재초점, 앱 시작 시 기본 재초점 동작은 기존 그대로 `overlay`의 현재 중심을 그대로 재사용).

### 3. `focusAt()`의 AF 리전 크기 확대

`regionSize` 계산의 비율 상수를 `0.05f` → `0.20f`로 변경. 나머지 로직(좌표 매핑, 트리거 전송)은 그대로.

### 4. `layoutPreview()` 폭 우선으로 단순화

`containerW / containerH > ratioWH` 분기를 없애고, 항상 `targetW = containerW`, `targetH = targetW / ratioWH`로 계산한다. `previewContainer`(FrameLayout)는 넘치는 자식 뷰를 자동으로 잘라서 그리므로 높이가 넘치면 위아래가 잘려 보이는 것은 허용한다(사용자 확인).

### 5. UI 통일 (색상 상수 + 버튼 스타일 + 여백)

`MainActivity`에 5개의 이름 붙인 색상 상수를 추가(`COLOR_BG`, `COLOR_ACCENT`, `COLOR_TEXT_SECONDARY`, `COLOR_BUTTON_NORMAL`, `COLOR_BUTTON_TEXT`) — 기존에 쓰던 값을 그대로 재사용해 시각적 변화는 최소화하면서 반복되던 리터럴을 정리한다. `buildUi()` 전체를 이 상수들을 쓰도록 교체하고, 모든 버튼(RAW 촬영/노출 스윕/줌/10·20·30%)에 동일한 배경/글씨색을 적용한다(선택된 비율 버튼만 강조색 유지). 상하 텍스트 줄의 패딩을 24/12/0 등 제각각이던 값에서 16(가로)/6(세로)로, 버튼 줄 마진도 통일한다. `refreshPercentButtonHighlight()`도 같은 상수를 쓰도록 정리한다.

## 데이터 흐름

```
사각형 안쪽 터치
  → overlay.containsPoint(x, y) == true
  → focusAt(overlay.getCenterX(), overlay.getCenterY()) — 사각형 위치는 그대로, AF만 재시도

사각형 바깥 터치
  → containsPoint == false → 아무 동작 없음
```

## 에러 처리

- `overlay`가 아직 크기를 갖기 전(`centerX < 0`)이면 `containsPoint`가 항상 `false`를 반환해 터치가 무시됨 — 기존 `focusAt()`의 가드들과 동일한 방어적 처리.

## 테스트 계획

`containsPoint()`는 기존 `SquareGeometry` 순수 함수를 그대로 재사용하는 얇은 판정 로직이라 별도 유닛 테스트 없이 진행하고(기존 프로젝트 컨벤션대로 Android `View` 관련 코드는 유닛 테스트 대상이 아님), 실기기 확인 항목으로 검증한다. 나머지(레이아웃/색상)도 실기기 육안 확인 대상:

- 사각형 안쪽을 터치하면 "포커스: 확인중" → "포커스: 완료"로 바뀌는지, 바깥을 터치하면 아무 반응 없는지
- AF 영역이 넓어진 뒤 초점이 이전보다 더 잘 잡히는지
- 프리뷰가 화면 폭을 꽉 채우는지(위아래가 약간 잘리는 건 정상)
- 모든 버튼이 같은 스타일로 보이는지, 선택된 비율 버튼만 강조색인지
